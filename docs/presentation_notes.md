# 当前级联流程汇报讲稿

面向没有RAG经验的组员，按以下10个主题讲解，约10分钟。本文件已更新为当前默认100→50→30→10流程；`deliverables/`中现有PPT及备注仍为历史100候选流程，尚未据此重建。以下主题不表示现有PPT已经有对应页面。

## 1. 我们解决什么问题（约40秒）

给定一个人的电影评分历史和100部候选，选出适合他的10部，并说明依据。默认分三轮：先用分数把100部缩为50部，再请重排模型选出30部，最后让Qwen结合完整历史从30部中选10部，让生成模型集中处理更小的范围。

RAG是“检索增强生成”：先从已有数据找依据，再让模型据此输出结果。这里检索的是电影信息和训练评分统计，输出是推荐列表。我们调用现成模型，没有训练或微调大模型。

## 2. 数据怎么来、答案藏在哪里（约1分钟）

数据来自MovieLens 100K，沿用教师脚本和固定种子20261018。共1682部电影、943位用户。脚本选30位验证用户，各留出最后5条评分，共150条；其余99850条评分进入训练集。其他用户的全部评分也进训练集，所以这不是全局统一时间切分。

每位验证用户的5部留出电影与95部从未评分电影组成100部候选。留出电影中至少4分的才算相关项，未评分电影不能解释为用户不喜欢。推荐时不给模型看留出评分，独立评测阶段才读取标签核对答案。

## 3. 表格如何变成可检索内容（约1分钟）

电影表提供编号、片名、上映日期和类型；训练评分表提供用户、电影、评分和时间。程序把编号转成整数，把类型拆成列表，建立按电影、按用户查询评分的索引。

每部电影形成一条短文档，写入元数据、训练评分人数、平均分和至少4分的次数。没有剧情或影评，也不让模型编造剧情作为证据。短文档无需切块；项目用NumPy计算相似度，没有额外部署向量数据库。

## 4. 如何理解用户偏好（约1分钟）

用全部训练历史计算各类型平均评分，在查询文本中补充最多8部高分、5部低分电影。例如用户对剧情片评分高、恐怖片评分低，这提供偏好线索，但不代表他一定喜欢所有剧情片。

Embedding模型将查询和候选文档转换成向量，可以理解为便于计算内容接近程度的一串数字。比较向量方向的余弦相似度，得到电影信息与用户偏好的接近程度。摘要只供检索使用，Qwen仍看到完整训练历史。

## 5. 粗筛：100部变成50部（约1分钟）

除了文本相似度，还参考相似用户的真实训练评分。程序将评分减3再除2构成用户向量，计算用户相似度，排除自己，最多取40位正相似邻居。对候选电影，将近邻评分按相似度加权，并加入中性项，降低少量支持带来的极端值。

粗筛分数为 `0.65*(cosine+1)/2 + 0.35*(cf+1)/2`。cosine是文本向量余弦相似度，cf是协同支持；换算到对应尺度后结合，保留前50部。这些权重为预设规则，没有读取验证标签进行调整。

## 6. 精筛：50部变成30部（约55秒）

Rerank模型直接阅读查询与50条电影文档，分别给出相关性分数。当前默认精筛仅按Rerank分数取前30，不在这一步再混合协同分数。

保留证据含编号、来源、训练统计和近邻评分，供模型判断和事后核查。Qwen可选范围被硬限制在这30部，被筛掉的电影不能在最终推荐中重新出现。

## 7. 生成、校验与理由（约1分钟）

Qwen看到完整历史、30候选与增强证据，从30部中选10，输出编号、排名、中文理由和引用。程序检查数量、去重、候选边界、历史排除、连续排名和引用；不通过时允许一次修正。

引用存在仍可能说错评分。因此最终理由由确定性程序按真实历史评分和共同类型渲染，缺少同类型高分依据时明确标为探索项；只有存在对应引用时才补充训练高分次数。选片和排序不变，原始理由保存在model_reason，原始响应保留用于审查。

## 8. 如何评测和做消融（约1分钟）

最终推荐仍与原始100候选的标签比较，不能把筛掉的相关电影从答案中删除。Recall@10看相关电影找回多少，NDCG@10还看命中位置。固定30位用户逐人计算后取平均，失败或非法输出计零。

热门基线在原100候选中按训练高分次数选10。新默认no_retrieval消融保留同一次筛选后的相同30候选和完整历史，只删增强证据，检验“给定30候选时证据是否有帮助”。新默认消融尚未重跑，历史formal中的100候选消融不能替代它。

## 9. 已完成的两流程对照（约1分15秒）

完整30用户对照中，两组均成功30/30。全100候选生成与级联生成的Recall同为0.450556；NDCG分别0.329620和0.326951。级联HitRate为0.866667，全候选为0.833333。指标方向不同，不能挑一个指标宣布全面提升。

级联每用户生成输入token减少19.27%，总token减少18.82%，Rerank token减少49.98%。平均生成耗时约19.35秒降到18.70秒，但调用时段与并发状态未严格控制，不能当成稳定加速比例。粗筛50部的相关覆盖约90.72%，精筛30部约78.56%，压缩候选也丢失了一部分相关电影。

这次对照同时改变粗筛、精筛打分与生成候选范围，不是只删证据的消融。30人配对bootstrap区间跨0，不足以证明准确性差异，也不能证明等效。当前最明确的收益是减少模型用量，详细依据保存在outputs/cascade_comparison。

## 10. 演示与下一步（约1分钟）

执行 `python run.py demo --name cascade_comparison --method cascade --user 20`，离线展示已有级联推荐，再核对一条理由的历史和类型来源，不调用模型。新默认实验可用 `python run.py experiment`，默认名称cascade，结果与历史formal分开保存。
