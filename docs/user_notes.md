# 项目进展与关键决定

我们选择题目一的 MovieLens 电影推荐 RAG。系统从给定 100 部候选电影中推荐 10 部并解释依据；不训练模型，不添加模型编写的剧情。

## 已确认的实现

- 按教师原脚本生成 student 开发数据，种子为 `20261018`，默认 30 位验证用户；官方 MovieLens 下载和 MD5 校验成功。没有自行更换划分方式。
- 使用 `qwen3.8-27b` 生成、`text-embedding-v4` 向量化、`qwen3-rerank` 重排。三个模型已完成真实 API 小请求验证，均返回 HTTP 200。
- 完成热门基线、检索、Qwen 推荐、结构化校验和独立评测的代码。热门基线仅统计训练集中评分 ≥4 的次数，同次数按电影编号排序。
- 消融选择移除检索证据，保留相同历史、候选、生成模型和配置，以观察检索证据的作用。
- 检索库和推荐不读取留出评分或验证标签。标签仅用于生成之后的离线评测和失败分析。
- 数据完整审计通过：1,682 部电影、943 位用户、99,850 条训练评分、150 条留出评分、30 位验证用户。30 项测试通过。
- 最终理由按真实历史评分及共同类型渲染；Qwen 原始理由和响应仍保留用于审计。42 份旧结果统一迁移，后续成功输出自动使用同一规则，最终 59 份成功输出的推荐电影和顺序完全未改。

## 当前进度

正式实验已结束。充值后服务恢复，原 18 份权限中断任务已续跑，未重跑已成功缓存。RAG 成功 30/30，移除检索的消融成功 29/30；消融用户 921 两轮仍返回候选外或历史已看电影，作为真实失败计零，未反复重试挑选成功结果。三种方法均以同一组 30 位用户为分母。

最终结果：

| 方法 | Recall@10 | NDCG@10 |
| --- | --- | --- |
| 热门基线 | 0.335556 | 0.273426 |
| RAG | 0.483889 | 0.346630 |
| 移除检索证据 | 0.262222 | 0.243269 |

此前的 18 份 HTTP 403 `AccessDenied.Unpurchased` 作为开发事件保留在 `outputs/formal/errors/`，历史费用单独列出，不作为最终推荐失败。报告和约 10 分钟汇报材料按最终结果生成到 `deliverables/`，文件为 `MovieLens_RAG_报告.md`、`MovieLens_RAG_报告.pdf`、`MovieLens_RAG_汇报.pptx`。

报告会如实呈现热门基线、RAG 和消融的表现；即使 RAG 不如基线也保留结果，并分析至少 3 位失败用户。推荐编号和证据引用校验通过，也仍需检查理由是否准确反映历史与证据。

## 使用与提交

完整命令见项目 `README.md`。正式结果保存后，可用 `demo` 命令直接展示，不再调用模型。API Key 只放本地 `.env`。

数据、标签、向量缓存和包含 MovieLens 内容的完整实验输出仅留本机；公共代码包只提供源码、配置模板和原始生成方式。报告及汇报按课程要求提交，并致谢引用 MovieLens。

按用户要求，成员姓名暂不填写；成员 1—8 只表示建议职责。实际贡献由小组按真实参与情况核实，不把建议分工写成已发生事实。
