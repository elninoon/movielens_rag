# 题目一要求与验收

依据：`01_作业说明/课程大作业_电影推荐与数据分析.docx`，以及教师附件 `02_学生附件/prepare_movielens.py`。本项目选择 RAG 路线，任务是 MovieLens 电影推荐。

| 要求 | 实现与验收依据 |
| --- | --- |
| 使用 Qwen API | 保存实际模型 ID、调用配置、Token 用量与运行记录；不以模拟输出代替正式模型实验 |
| 使用 MovieLens 100K 和教师数据准备脚本 | 使用 `student` 模式、种子 `20261018`、默认 30 位验证用户；保留 `split_manifest.json` |
| 根据用户训练历史，从给定的 100 部候选中推荐 10 部 | 默认按100→50→30→10处理；Qwen输出限于筛选后的30部，最终结果也须属于原始100部、历史外、不重复，排名为1—10 |
| 每部推荐具有简短、可核查的理由 | 结构化输出电影编号、排名、理由及依据；依据仅来自训练历史、电影元数据或实际检索证据 |
| 明确 RAG 检索设计 | 报告说明检索对象、检索依据、返回条数、如何交给 Qwen；保存实际检索证据 |
| 检索库不含测试评分或正确答案 | 检索与推荐模块仅读取电影元数据、训练评分和输入 case；标签只由离线评测读取 |
| 实现热门推荐基线 | 按训练集中评分 ≥4 的次数降序，次数相同按电影编号升序，在同一候选集合中取前 10 部 |
| 完成一次消融实验 | 例如移除检索证据；除被测试部件外，用户、候选、模型、提示词其余内容及生成配置保持一致 |
| 分析至少 3 位验证失败用户 | 对照实际命中、训练历史和检索证据，分析偏好判断、检索遗漏或候选排序；检查理由是否一致 |
| 如实呈现实验 | 模型结果低于热门基线也如实报告；不把未执行实验、预估值或模拟结果写成实测结果 |
| 提交报告和约 10 分钟汇报 | 包含成员分工、目标、方法与过程、结果、反思；报告各结论对应真实运行产物 |
| 完成周期为两周，每组 6—8 人 | 八人分工覆盖数据、基线、检索、生成、集成、评测及报告汇报 |

## 范围

只实现 RAG 方法即可，不要求再独立实现提示词方法；移除检索的消融属于实验对照。无需训练或微调模型，不强制 Agent、多轮工具调用或网页界面，命令行、Notebook 或百炼应用均可。

MovieLens 100K 没有完整剧情或影评。基础实现只使用原始电影编号、片名、上映信息、类型及训练评分。不把模型常识或生成剧情写成检索证据；如确需外部资料，必须注明真实来源。

## 当前默认流程与验收状态

默认实验名为 `cascade`。先在教师给定的100部候选中，用 `0.65*(cosine+1)/2 + 0.35*(cf+1)/2` 粗筛50部，再仅按Rerank模型分数保留30部；Qwen看到完整训练历史、这30部候选及其增强证据，生成10部推荐。`cosine`为用户偏好查询与电影文档的向量余弦相似度，`cf`为相似用户训练评分提供的协同支持分。评测始终使用原始100候选与原始标签，不因筛选丢失相关电影而缩小相关集。

`no_retrieval` 消融复用同一次筛选得到的30部候选，只删除交给Qwen的增强证据；历史、候选、模型配置和理由渲染规则保持一致。因此它检验的是“给定相同30候选时，增强证据是否有帮助”，不检验整个筛选流程的收益。当前30用户实验已完成：热门和级联RAG合法30/30，消融合法29/30；用户528两次HTTP200均引用不存在的 `history_17`，作为真实内容失败计零，不重新抽样。首次输入一致性核查30/30通过，指标固定使用30人分母。

当前报告主结果使用 `outputs/cascade/`：复用已核对的30份级联RAG及检索记录，新增同候选消融32次请求、273881 total tokens，热门基线重新离线计算。指标、用量、三个真实漏推荐案例及报告/PPT制作要求统一见 [README事实包](../README.md#已完成的实验与结果报告主结果)。本机 `summary.json`、`summary.md` 保存离线核验明细。

`outputs/cascade_comparison/` 为辅助的全100候选生成与级联生成对照，两组均成功30/30；它同时改变粗筛、精筛打分与生成候选范围，不属于只删除增强证据的消融。原始复用来源记录在 `outputs/cascade/provenance.json`，复用调用不能计作本次新增调用。

`outputs/formal/` 和 `deliverables/` 属于历史100候选流程的实验与交付材料。当前默认切换不代表历史报告或PPT已经更新。`scripts/build_report.py`、`scripts/build_deck.mjs` 仍按历史 `outputs/formal/` 结果构建材料；重新提交前需基于新默认真实实验结果更新材料，不能把运行旧构建脚本视为更新到新默认。

## 数据与引用

原始压缩包和生成的 `movies.csv`、`train_ratings.csv`、验证输入、标签与派生数据仅供本组本地课程开发，不上传公共仓库、不随代码包再次分发。交付代码提供官方脚本和重新生成命令。

报告致谢 MovieLens，并引用：F. Maxwell Harper and Joseph A. Konstan. 2015. *The MovieLens Datasets: History and Context*. ACM Transactions on Interactive Intelligent Systems 5(4), Article 19. DOI: [10.1145/2827872](https://doi.org/10.1145/2827872)。
